# ADR-0003: 日次スナップショットからセラーの SCD Type 2 を手書きで実装する

**日本語** | [English](../en/0003-scd2-sellers.md) | [中文](../zh/0003-scd2-sellers.md)

**ステータス:** 採用

## 背景
セラーのフィードは毎日の全件スナップショットです。セラーはときどき所在地（市・州）を移転します。地域別の配送パフォーマンスは、現在の所在地ではなく、**注文時点の所在地**で集計する必要があります。

## 決定
- `silver.seller_history` は `seller_sk`、`valid_from`、`valid_to`（この日を含まない）、`is_current` を持ちます。
- 変更検知には、追跡対象の属性（郵便番号上位桁・市・州）の SHA-256 ハッシュを比較します。
- スナップショット全体を1回の MERGE で適用します。変更行を2回ステージングする定番の手法を使い、`merge_key = seller_id` の行で旧バージョンをクローズし、`merge_key = NULL` の行（必ず不一致になる）で新バージョンを挿入します。
- 最初に観測したバージョンの有効開始日は `1900-01-01` とします。最初のスナップショット以前の履歴は存在しないため、どのセラーにも結び付かない注文が生じるよりは、「最初に観測した属性がそれ以前も有効だった」とみなすほうが妥当と判断しました。
- スナップショットに含まれないセラーも現行のまま残します。スナップショットからの欠落は削除を意味しません。
- 障害後などで一つのマイクロバッチに複数日分のスナップショットが入った場合は、日付順に適用します。
- ファクトテーブルとは `valid_from <= 注文日 < valid_to` で結合します。

## 検討した代替案
- **SCD1（上書き）:** 地域別指標に必要な履歴が失われます。
- **Lakeflow の `AUTO CDC ... STORED AS SCD TYPE 2`:** 正確で簡潔ですが、本プロジェクトで示したい仕組みそのものが隠れてしまいます（ADR-0008）。

## 影響
- 同じスナップショットを再適用しても、ハッシュが一致するため何も変わりません。
- テスト: `test_scd2_keeps_history_and_is_idempotent`、`test_fact_uses_the_seller_version_valid_on_the_order_date`、およびクローズされたバージョン数が注入した移転数と一致することを確認する E2E テスト。
