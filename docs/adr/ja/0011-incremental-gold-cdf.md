# ADR-0011: Change Data Feed による Gold の増分処理

**日本語** | [English](../en/0011-incremental-gold-cdf.md) | [中文](../zh/0011-incremental-gold-cdf.md)

**ステータス:** 採用

## 背景
v0.3.0 までは、毎回の実行で Silver 全体から Gold のファクトを作り直して MERGE し、ハッシュが変わった行だけを書き直していました。日次バッチで変わる Silver の行は約10万行のうち1,000〜2,000行なので、読み込みと結合のほとんどは繰り返しの作業です。この規模ではコストは小さいものの（サーバーレスで Gold は約90秒、その多くは起動時間）、履歴とともに増えていきます。

## 決定
- **Silver のソースで Change Data Feed を有効にする。** Gold は読み込むすべてのテーブルで CDF を（冪等に）有効にします。変更はその時点からしか記録されないため、ウォーターマークのないソースは必ず全件の再構築から始まります。
- **（ファクト, ソース）ごとのウォーターマーク**を `ops.gold_watermarks` に保存します。実行の最初に各ソースの現在のバージョンを上限として固定し、`(ウォーターマーク, 上限]` の変更を読み、**ファクトの MERGE が成功した後でだけ**上限を新しいウォーターマークとして保存します。失敗した実行は次回もう一度処理されるので、取りこぼしはありません。
- **変更を影響を受けた注文に変換します**（間接的な影響も含みます）。その注文だけを Silver から作り直して MERGE します。

  | ファクト | ソースと、変更から注文への対応 |
  |---|---|
  | `fact_order_item` | 明細・注文 → その注文、顧客 → その顧客の注文、セラーの新バージョン → そのセラーの注文 |
  | `fact_order_fulfillment` | 注文の変更・明細・レビュー → その注文、顧客 → その顧客の注文 |

- 次の場合は**代わりに全件を再構築します**：ターゲットが存在しない、ソースにウォーターマークがない、必要なバージョンの変更データが既に消えている（Delta は保持期間の間しか残しません）、ジョブが `full_refresh=true` で実行された。理由は記録します。
- **毎回の実行を計測します**：モード、理由、作り直した注文数、全注文数を `ops.gold_incremental_stats` に書き込み、ダッシュボードに表示します。
- **日次の注文残スナップショットは全件再構築のままにします。** 日付で集計しており、遅れて届いた変更はかなり前の日を修正し得ます。どの日を再計算すべきかを決めるのは「どの注文か」とは別の、より難しい問題で、一方で全件再構築は数秒で終わります。遅くなったら見直します。

## 実データでの結果
- 11回の実行の後、両ファクトは**全件再構築と完全に一致します**（93,465 行と 82,406 行、差分 0）。
- 初回は全件で、それ以降の各実行で作り直すのは注文の **0.44%〜1.89%**、通常の日で約1%です。
- 約10万行の規模では、サーバーレスの起動時間が大半を占めるため、実際の短縮時間は小さいです。価値はこのパターンと、処理量が履歴とともに増えなくなったことにあります。

## 検討した代替案
- **変更フィードをチェックポイント付きでストリーミングする：** ソースが1つなら自然ですが、4つのソースに依存するファクトでは扱いにくくなります。ウォーターマークのテーブルなら、確認する場所もコミットする時点も1つで済みます。
- **変更された行のキーで直接 MERGE する（注文への対応付けなし）：** 顧客の変更がその顧客の注文に及ぶ、といった間接的な影響を取りこぼします。
- **注文残も増分化する：** 上記のとおり、意図的に後回しにしています。

## 影響
- 正しさは3つの方法で守ります。テストでリプレイした各日の後に増分の結果を全件再構築と比較し（ゲートで止まった日と追い付きの実行も含みます）、`full_refresh` のスイッチを用意し、信頼できない場合は常に全件へフォールバックします。
- テスト：`tests/test_incremental.py`（初回は全件でその後は増分、新しい変更がない場合、全件の指定が優先されること、変更データがない場合のフォールバック、成功後にだけ進むウォーターマーク、統計）と、E2E のチェック2件（全件再構築との一致、初回以降は増分であること）。
