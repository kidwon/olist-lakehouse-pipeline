# ADR-0006: 明示的なデータ契約を定め、未知のフィールドは推論せず退避する

**ステータス:** 採用

## 背景
JSON のスキーマ推論に任せると、送信元が私たちのテーブルを変えられてしまいます。新しいフィールドは新しい列になり、型が変われば下流のコードが壊れ、しかも誰もそれを決めていません。リプレイの途中で、明細の送信元は `discount_amount` を送り始めます。

## 決定
- すべてのフィードは `contracts.py` に明示的なスキーマを持ちます。
- JSON Lines はテキストとして読み、`from_json(契約スキーマ)` でパースします。契約にないキーは JSON として `_rescued_data` に退避します。JSON オブジェクトでない行には `_malformed` を立てます。
- Bronze には元の行（`_raw`）を残します。将来契約を改訂したときに、ファイルを再取り込みせず Bronze からバックフィルできます。
- 退避フィールドを持つ行は `rescued_data`（重要度 `warn`）として計上します。新しいフィールドの採用は、契約の変更として意図的に行います。

## 検討した代替案
- **Auto Loader の `addNewColumns`:** スキーマを自動で拡張し、ストリームを再起動します。便利ですが、決定権が送信元に移ります。
- **Auto Loader の `rescue` モード:** 考え方は同じですが、Databricks 上でしか動きません。本実装のパーサーは、ローカルでも CI でも同じように動作します。

## 影響
- テスト: `test_unknown_fields_are_rescued_not_dropped`。E2E テストでは、退避された行数が新フィールドを含んでいた行数と一致します。
